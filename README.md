# NOVA HR · เวอร์ชัน 4

รูปแบบเดียวกับ POS ที่อ้างอิง: **Google Sheets = ฐานข้อมูล · Apps Script = API · GitHub = ซอร์สโค้ด · Netlify = หน้าเว็บ**

## โครงสร้าง

- `apps-script/` — นำไฟล์ `.gs` ทั้ง 8 ไฟล์ใส่ในโปรเจกต์ Apps Script เดียวกัน
- `public/` — เว็บมือถือ/คอม รวมหน้าสแกนใบหน้า ที่ Netlify เสิร์ฟได้โดยไม่ต้อง build
- `netlify.toml` — ตั้งค่า publish directory เป็น `public`
- `public/js/config.js` — URL ตั้งต้นของ Apps Script (ปล่อยว่างได้; กรอกบนหน้าล็อกอินแทน)
- `tests/` — ตรวจเส้นทางสำคัญของ API และการแสดงหน้าจอด้วย Google Apps Script จำลอง

## 1. Apps Script และฐานข้อมูล

1. เปิด Google Sheet `Nova.3` → **ส่วนขยาย → Apps Script**
2. ใส่ไฟล์ `Setup.gs`, `Util.gs`, `Code.gs`, `Attendance.gs`, `Leave.gs`, `Users.gs`, `Face.gs`, `Calendar.gs` จากโฟลเดอร์ `apps-script/` ในโปรเจกต์เดียวกัน ชื่อไฟล์ตรงกัน แล้วบันทึก
3. เลือก `setupAll` → **เรียกใช้** → อนุญาตสิทธิ์
4. รีเฟรช `Nova.3`: ระบบสร้างชีต Users, Accounts, FaceTemplateIndex, CalendarDays, ตารางวันหยุด, LineLog, Attendance, Config, Shifts, LeaveTypes, LeaveRequests และ AuditLog ให้เอง
5. ดู **บันทึกการดำเนินการ** เพื่อรับ PIN ครั้งแรกของ `OWNER` แล้วเก็บ PIN ไว้ เจ้าของธุรกิจควรเปลี่ยน PIN ในหน้าตั้งค่าหลังเข้าสู่ระบบ

`setupAll` รันซ้ำได้: เติมเฉพาะชีต คอลัมน์และค่าเริ่มต้นที่ขาด ไม่ลบแถวข้อมูล โครง Attendance 15 คอลัมน์แรกตรงกับ `Nova.3.xlsx` และใช้วันที่ ค.ศ. ถ้า PIN เจ้าของธุรกิจหาย ให้เรียก `resetOwnerPin` จาก Apps Script editor เพื่อสร้าง PIN ใหม่

### Deploy Web App

1. ใน Apps Script เลือก **การทำให้ใช้งานได้ → การทำให้ใช้งานได้รายการใหม่ → เว็บแอป**
2. **เรียกใช้ในฐานะ: ฉัน** และ **ผู้มีสิทธิ์เข้าถึง: ทุกคน** แล้ว Deploy
3. คัดลอก URL ที่ลงท้าย `/exec`
4. เปิด URL `/exec` ในเบราว์เซอร์ ต้องเห็น JSON ที่มี `"ok":true` และ `"pong":true`
5. หลังแก้โค้ด Apps Script ครั้งต่อไป ให้สร้าง **เวอร์ชันใหม่** ในการจัดการการทำให้ใช้งานได้ URL `/exec` เดิมจึงใช้ต่อได้

เว็บส่งคำสั่ง POST แบบ `text/plain` ตามแบบ POS และส่ง session token หลัง login; Apps Script ตรวจบทบาททุกคำสั่งที่เปลี่ยนข้อมูล PIN เก็บเป็น hash พร้อม salt ในชีต Accounts ไม่มี PIN ในซอร์สเว็บหรือ GitHub

## 2. เว็บบน GitHub

สร้าง repo GitHub แล้วอัปโหลด **เนื้อหาทั้งโฟลเดอร์ `เวอร์ชัน_4`** ให้ `netlify.toml` และ `public/` อยู่ที่ root ของ repo หรือถ้าใช้ repo ใหญ่ ให้ตั้ง Base directory ใน Netlify เป็น `ระบบ/เวอร์ชัน_4`

ไฟล์ `apps-script/` เก็บใน GitHub เป็นซอร์สโค้ด แต่ Apps Script editor เป็นที่รัน API ของ Google; การ push GitHub อย่างเดียวจะไม่อัปเดต Apps Script เว้นแต่ติดตั้ง pipeline เพิ่ม

## 3. Netlify

เชื่อม repo GitHub กับ Netlify และตั้งค่า **Publish directory: `public`** ไม่ต้องมี build command `netlify.toml` ในชุดนี้กำหนดค่าให้แล้ว

เปิดเว็บ Netlify → หน้าแรกสแกนใบหน้า → **เข้าสู่ระบบ** มุมบน → **ตั้งค่าการเชื่อมต่อ Apps Script** → วาง URL `/exec` → บันทึก URL → ตรวจการเชื่อมต่อ → เข้าระบบด้วย `OWNER` และ PIN ที่ได้จาก `setupAll` URL ถูกจำใน browser เครื่องนั้น อีกทางหนึ่งคือใส่ URL ตั้งต้นใน `public/js/config.js` ก่อน push GitHub เพื่อให้ทุกเครื่องเห็น URL เดียวกัน URL นี้เป็น endpoint สาธารณะได้ แต่ห้ามใส่ PIN หรือ token ลับในไฟล์ดังกล่าว

## สิทธิ์และข้อมูล

- **เจ้าของธุรกิจ / Admin**: เพิ่มพนักงานและหัวหน้าแผนก, รีเซ็ต PIN, อนุมัติเวลา/ลา, แก้ชั่วโมง OT พร้อมเหตุผล, ตั้งค่า OT, ดูรายงานทั้งหมด
- **หัวหน้าแผนก / Admin**: เพิ่มพนักงาน, อนุมัติเวลา/ลา, แก้ OT, ตั้งค่า OT, ดูรายงานทั้งหมด
- **พนักงาน**: ลงเวลาเข้า–ออก, ยื่นลา, ดูประวัติตนเอง, เปลี่ยน PIN

### หน้าแรกสแกนใบหน้า

เปิดเว็บแล้วเห็นหน้าสแกนทันที ระบบลองเปิดกล้องอัตโนมัติ หาก browser ต้องการการกดจากผู้ใช้ ให้กด **เริ่มสแกนใบหน้า** เมนู **เข้าสู่ระบบ** อยู่มุมบน พนักงานและ Admin ยังมีหน้าสแกนในบัญชีของตนด้วย

เมื่อหน้าแรกสแกนพบพนักงานที่ลงทะเบียน ระบบจะเลือก **เข้างาน** หรือ **ออกงาน** จากรายการค้างของพนักงานคนนั้นแล้วบันทึกโดยไม่ต้องกรอก PIN ก่อน 09:00 พูด “ยินดีต้อนรับ”; ตั้งแต่ 09:00 พูด “เข้างานสายนะคะ”; ออกงานพูด “ออกงาน บ๊ายบาย” ใช้เสียงภาษาไทยของเครื่องที่ตั้ง pitch สูง เสียงเด็กจริงขึ้นกับเสียงที่ browser/อุปกรณ์มี หลังสำเร็จต้องกดเริ่มสแกนอีกครั้งสำหรับคนต่อไปเพื่อป้องกันลงเวลาออกทันที หากไม่มีการใช้งาน 30 วินาที หน้าสแกนพักหน้าจอ; แตะเพื่อปลุก

Admin เปิด **ตั้งค่า → ลงทะเบียนใบหน้าพนักงาน** เลือกพนักงาน ยืนยันว่าพนักงานรับทราบ แล้วสแกนใบหน้า 1 คน หน้าตั้งค่าแสดงสถานะใบหน้าของแต่ละคนและลบข้อมูลได้ ระบบเก็บ **เวกเตอร์ลักษณะใบหน้า 128 ค่า** ใน Apps Script Script Properties และเวลา/สถานะใน FaceTemplateIndex; **ไม่เก็บรูปภาพต้นฉบับ** เมื่อ Admin ลบพนักงาน ระบบปิดบัญชี ลบเวกเตอร์ใบหน้า และคงประวัติงานไว้

หน้า **ประวัติและรายงาน** มีปุ่มแก้ไขสำหรับ Admin แก้วันที่ เวลา กะ นาทีสาย และกระจาย OT 1.0/1.5/2.0/3.0 พร้อมเหตุผล ระบบคำนวณชั่วโมงทำงานใหม่ ตั้งรายการเป็นรออนุมัติ และบันทึก AuditLog ค่าเริ่มต้นของการลงเวลาออกยังจัด OT เกินเวลามาตรฐานใน 1.5x

Admin เปิด **ตั้งค่า → ประเภทการลา** เพื่อเพิ่มหรือแก้รหัส ชื่อ จำนวนวันต่อปี การได้รับค่าจ้าง วันหมดอายุ และสถานะ หากมีคำขอใช้ประเภทนั้นแล้ว ระบบไม่ให้เปลี่ยนชื่อเพื่อคงประวัติและยอดสิทธิ์เดิม

หน้า **ปฏิทิน** เห็นได้ทุกบัญชี: เขียว = มาทำงาน, แดง = วันหยุดที่ Admin กำหนด, เทา = ลาที่อนุมัติแล้ว (ลากิจ/ลาป่วย/ลาพักร้อน) วันที่ไม่มีรายการยังไม่กำหนดสถานะ Admin เพิ่มและยกเลิกวันหยุดได้บนหน้านี้

กล้องใช้ได้บน HTTPS ของ Netlify เมื่อผู้ใช้อนุญาต ต้องออนไลน์เพื่อโหลด face-api.js 0.22.2 จาก jsDelivr และโมเดลจาก jsDelivr (ไฟล์ต้นทางใน GitHub face-api.js/weights) เกณฑ์การจับคู่เริ่มต้น 0.45 อยู่ใน Config (`ระยะเทียบใบหน้าสูงสุด`) ควรปรับหลังประเมินกับพนักงานจริง

หลังอัปเดตจากเวอร์ชันก่อน ต้องเพิ่ม `Calendar.gs`, อัปเดตไฟล์ `.gs` ทุกไฟล์, รัน `setupAll()` ซ้ำเพื่อสร้าง CalendarDays/ประเภทลากิจ แล้ว **Deploy เวอร์ชันใหม่ของ Web App** หน้าเว็บเก่าที่ Netlify ต้องเผยแพร่ไฟล์ `public/` ชุดนี้ด้วย

เวลาและวันลาถูกบันทึกใน Google Sheet ผ่าน Apps Script การอนุมัติและการแก้ OT เขียน AuditLog ค่าเริ่มต้นคิดเวลาพัก 60 นาที กะเช้า 08:00–17:00 กะปกติ 09:00–18:00 ผ่อนผันสาย 9 นาที และจัด OT ที่เกินชั่วโมงมาตรฐานไปที่ 1.5x ก่อนให้ Admin ตรวจ ปรับนโยบายจริงก่อนนำไปคำนวณค่าจ้าง

ค่าตัวคูณ OT 1.0x/1.5x/2.0x/3.0x ถูกเก็บใน Config สำหรับนโยบายและรายงาน ระบบรุ่นนี้ยังไม่คำนวณยอดเงินค่าจ้าง เพราะไม่มีฐานค่าจ้างรายคนในข้อมูลที่ให้มา

## ตรวจระบบก่อนเผยแพร่

ใช้ Node.js รันจากโฟลเดอร์ `เวอร์ชัน_4`:

```sh
node tests/backend-smoke.cjs
node tests/ui-smoke.cjs
node tests/face-smoke.cjs
```

ชุดนี้จำลอง Google Apps Script และกล้องเพื่อเช็คการสร้างชีตซ้ำ, login/สิทธิ์, ลงเวลา, ลา, อนุมัติ, ตั้งค่า, session หลังเปลี่ยน PIN และการสร้างเวกเตอร์ใบหน้าด้วยโมเดลจำลอง ยังต้องลองกับกล้องจริงบน HTTPS และ Apps Script/Google Sheet หลัง Deploy เพราะการจำลองไม่ครอบคลุมสิทธิ์กล้องหรือ Google และการเรียก Web App ข้ามโดเมน

## ข้อจำกัดก่อนใช้จริง

หน้าแรกส่งเวกเตอร์ใบหน้าไป API ที่ไม่ต้องล็อกอินเพื่อค้นหาพนักงานที่ลงทะเบียน การจับคู่ใบหน้าผ่านเวกเตอร์ยัง **ไม่มีการตรวจภาพปลอม/วิดีโอ (liveness)** และเวกเตอร์ที่เคยได้มาอาจถูกส่งซ้ำผ่าน API ได้ จึงยังไม่ใช่หลักฐานยืนยันตัวตนที่ปลอดภัยสำหรับงานค่าจ้างหรือการควบคุมสิทธิ์สูง Script Properties ไม่ใช่คลังข้อมูลชีวมิติที่เข้ารหัสแยกและมีข้อจำกัดด้านขนาด; ระบบนี้เหมาะกับการนำร่องในทีมเล็กก่อนเลือกบริการยืนยันตัวตนที่มีการตรวจ liveness และนโยบายคุ้มครองข้อมูลส่วนบุคคลที่เหมาะสม

ยังไม่ได้ตรวจ GPS ขณะลงเวลา การเข้าระบบใช้ PIN และ session token อายุสูงสุด 6 ชั่วโมงผ่าน Apps Script/CacheService จึงควรใช้ PIN ที่ไม่ซ้ำและจำกัดสิทธิ์การเข้าถึง Google Sheet ให้เฉพาะผู้ดูแล ผู้ใช้เว็บไม่ควรเปิดชีต Accounts โดยตรง
